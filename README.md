# 悦临平 H5 接口测试（GitHub Actions）

无需安装油猴。脚本使用你指定的 Android UA（包含 `YUNXH-YDAPP/1.0`），直接调用 H5 已使用的接口。

这是获授权账号的接口灰度测试器，不代表真实 App 内停留的端到端测试。支持每日真实签到、随机启动延迟、多账号独立执行，保留手动 inspect/signin 和原单账号命令。它不提前伪造停留时长、不绕过验证码或定位、不抽奖。它可能因为服务端环境校验、凭证或协议变化而失败；失败会停止，不保证一定能签到或避免账号限制。

## 第一次怎么用

1. 建一个你自己管理的 **GitHub 私有仓库**。
2. 将本文件夹里的内容放到仓库根目录，保留 `.github/workflows/linping.yml` 路径。不要把整个 `linping-actions` 文件夹再套一层。Windows 中 `.github` 文件夹可能是隐藏的。
3. 仓库 `Settings → Secrets and variables → Actions → Secrets → New repository secret`，新增 `LINPING_TOKEN`，值填写你之前复制的 **Access-Token 本身**。不要加引号，不要粘贴整份请求头 JSON。代码中未内置真实 Token。
4. 在仓库 `Actions` 中找到“悦临平 H5 接口测试”，点击 `Run workflow`。第一次保持 `mode=inspect`。
5. 检查输出是否显示：测试账号 `19426008`、正确的当前金币余额、活动编号和今日签到状态。180 是你此前观察到的值，不是脚本固定余额。
6. 确认身份正确后，再次 `Run workflow`，选择 `mode=signin`，`max_wait_minutes=200`。服务端要求 10800 秒（3 小时），200 分钟只提供客户端等待缓冲，不会伪造已停留时长；可以关闭自己电脑上的网页，GitHub 的任务仍会运行。

单账号仍只需要一个必填 Secret：`LINPING_TOKEN`。可选 `LINPING_DEVICE_ID` 是设备会话初始化使用的设备标识；留空时保留原来的生成行为。多日测试建议填写该账号获授权测试设备的固定标识，不轮换设备身份。脚本按 H5 的 `_auth_dt` 流程取得设备令牌，这不是刷新用户 Token。不要把 App 密码或短信验证码填到这里。单账号默认预期用户 ID 为 `19426008`，也可通过仓库变量 `LINPING_USER_ID` 显式指定其他获授权测试账号；不会从 Token 猜测用户身份。

注意：此版本上传到默认分支后，每日定时任务会真实运行签到，不再只是离线测试。离线测试仍是每次运行的前置检查。

## 两种运行方式

- `inspect`：获取设备会话、验证测试账号、读取公开活动规则、检查今日签到状态。不创建停留会话，不领取金币。
- `signin`：先做上述检查；今日未签到且没有额外验证限制时，创建停留会话，实际等待，每分钟请求一次 checkpoint。只采用服务端 `eligible` 状态，在提交前再次检查身份、今日记录、活动规则及会话资格，然后只尝试一次签到。最后检查今日记录和金币变化。

页面编号 `621` 不是签到活动编号。脚本从页面的 `signin` 组件读取活动 ID。2026-10-28 检查公开配置时，活动 ID 为 `10609040`，停留要求为 `10800` 秒（3 小时）；运行时会重新读取，不硬编码活动 ID。

请求签名包含随机值和当前时间，每次按当前 H5 逻辑重新生成，不复用你抓包里的旧 `Access-Api-Signature`。公开租户签名配置仅在运行进程中读取，不输出、不保存。程序不尝试伪造 App 原生登录信息。

## 每日自动签到与随机启动

工作流每天北京时间 **09:20**（UTC 01:20）触发：先离线自测，再校验配置、生成计划，然后对每个账号运行真实 `signin`。不需要每天点击 Run workflow，也不需要额外设置 `ENABLE_SCHEDULE`。工作流必须位于仓库默认分支，并且 Actions 已启用。

每个账号每天独立抽取 **0～60 分钟**的启动延迟。计划窗口从当次准备任务生成计划时开始计算；调度无延迟时，通常约北京时间 09:20～10:20 开始业务流程。随机等待阶段不发业务请求、不创建停留会话，之后才开始真实累计服务端要求的停留时间。三小时规则下，最终签到通常比开始业务流程晚至少三小时。

可在 `Settings → Secrets and variables → Actions → Variables` 添加 `RANDOM_WINDOW_MINUTES`，设置为 `0～90` 的整数：默认 `60`，`0` 表示不随机延迟。每日任务固定选择 `signin`、等待上限 `200` 分钟；手动运行仍使用你选择的模式和等待上限，立即启动、不额外随机等待。改变每天的基准时间需修改 `.github/workflows/linping.yml` 的 cron（UTC）。

GitHub 调度、准备过程及运行器排队可能延迟，不能保证精确卡在窗口内或补跑漏掉的任务。每批最多并行 3 个账号，更多账号会排队，因此可能明显晚于计划窗口启动；若旧计划跨了北京时间日期，会停止，不跨日补跑。整个工作流禁止与另一轮重叠，排队期间不会重复创建同一轮账号任务；运行时仍检查今日签到记录。请勿在运行中修改账号数组的顺序或内容，应等当前工作流结束再更新 Secret。

每个账号单独一个任务和结果摘要，一个账号过期或失败不会取消其他正在运行的账号。任务最长 330 分钟，包含最多 90 分钟随机等待、200 分钟停留预算和缓冲。随机启动仅用于灰度测试错峰，不提供反检测或免封号保证。

## 多账号配置

在仓库 Actions Secrets 添加 **`LINPING_ACCOUNTS`**，值为以下格式的 JSON 数组（仅为格式示例，请替换全部示例值）：

```json
[
  {
    "user_id": 19426008,
    "token": "替换为账号一的完整Access-Token",
    "device_id": "replace-with-authorized-device-one"
  },
  {
    "user_id": 19426009,
    "token": "替换为账号二的完整Access-Token",
    "device_id": "replace-with-authorized-device-two"
  }
]
```

- `user_id`：该 Token 所属用户的真实数字 ID，用于请求头和操作前后的身份校验。第二个示例 ID 不代表已验证存在的测试账号。
- `token`：该账号自己的有效 H5 Access-Token，不要包含整份请求头。
- `device_id`：该账号获授权测试设备的固定设备标识，用于 `_auth_dt` 初始化；不是已经截取的临时设备令牌。应来自各自获授权的独立测试设备，不要复制同一个设备 ID 到多个账号，也不要轮换指纹来逃避规则。

最多配置 10 个获授权账号；重复账号、Token 或设备标识，以及字段缺失、拼写错误都会在请求前被拒绝。每个账号单独初始化 Client、设备会话及停留会话，不共享认证状态；租户仍严格限定为 59，真实身份不匹配会停止。

`LINPING_ACCOUNTS` 非空时优先使用整份数组，原有 `LINPING_TOKEN/LINPING_DEVICE_ID/LINPING_USER_ID` 不会额外再执行一遍；JSON 错误也不会偷偷回退到旧账号。删除或清空该 Secret 才恢复原单账号配置。每日和手动工作流都会处理所配置的全部账号，首次建议手动选择 `inspect` 核对每个账号。

凭证只从 Secrets 注入，任务矩阵只包含账号索引和数值计划时间，不导出 Token、设备标识或整份账号 JSON。执行器也会对提取出的凭证设置日志遮罩。原命令 `node scripts/linping.mjs` 仍按单账号环境变量运行；新的 `node scripts/daily.mjs --account 0` 用于选定数组中第一个账号。

多账号和实际等待会增加 GitHub Actions 运行器用量：一个账号仅三小时停留就约占 180 分钟，随机等待也占用运行器。请按仓库套餐和计费设置核对额度，并在灰度结束后通过 Actions 页面禁用工作流，避免持续运行。

## 账号与自动化风险

手动及每日 `signin` 会从 GitHub 云端运行器访问账号，并携带项目中配置的 App 风格 UA/客户端头。按你确认的授权，本项目用于黑盒灰度测试；授权不代表服务端风控自动豁免。你提供的 App 提醒包含设备及多账号限制，请确保测试方已批准这些账号和云端执行环境，必要时申请测试白名单。不要用多仓库重复执行、伪造停留时长或绕过额外验证。

代码中的防重复和失败停止措施用于避免误操作：运行前核对账号与今日签到状态；等待上限不足时不创建会话；只有服务端确认达标才提交；签到最多尝试一次，网络错误不自动重试。它们只能减少重复请求和误触发，不能保证平台不会进行风控或封禁。

## Token 过期怎么处理

1. **目前能确定可用的方式**：在 App 正常登录后，重新打开这个 H5，从该页面成功请求中取得新的 `Access-Token`。单账号更新 `LINPING_TOKEN` Secret；多账号更新 `LINPING_ACCOUNTS` 中对应条目的 `token`，保留其他账号条目和顺序。等正在执行的任务结束后再更新，再手动跑 `inspect` 核对身份，无需改代码。
2. **自动续期还没有证据**：本次检查的 H5 登录链路中，没有确认可用的 `refresh_token` 接口。App 使用原生登录资料换取 H5 Token；仅有一个过期的 H5 Token，不能凭空换出新的登录凭证。
3. **以后可以接入的正规方式**：如果拿到项目正式的测试账号登录/刷新接口，或可安全提供的 App 会话刷新凭证，再单独实现续期；先验证新 Token 的账号一致后再使用。不能只修改 Token 内的时间字段。

每次请求更新的是 **接口签名**，不是 **用户 Token**。保持定时请求也不代表 Token 会自动续期。不能保证复制一次永久可用。

之前在聊天中公开过的 Token 建议测试后在 App 退出重登并确认旧令牌失效，或通过平台正式撤销。不要继续把新的 Token、完整请求头、HAR 抓包文件贴进聊天、Issue 或仓库。

## 常见结果

- **登录失效/需重新认证**：更新 Secret，先运行 `inspect`。不会反复尝试登录。
- **请求被拒绝（401/403）**：可能是登录、签名、设备或环境检查，不能直接断定只是 Token 过期。
- **业务码 1007**：服务器不认可当前资格；停止，未反复尝试。
- **达到等待上限**：没有成功累计所需进度，未提交。这里不伪造时长或直接尝试领取。
- **会话关闭/过期/结构变化**：本次停止，不无限重建会话。
- **签到接口成功但记录未确认**，或提交阶段超时：先到 App 看真实签到记录和余额，不要立即重跑。
- **今日已签到**：直接结束，不重复提交。
