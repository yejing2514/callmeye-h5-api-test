# 悦临平 H5 接口测试（GitHub Actions）

无需安装油猴。脚本使用你指定的 Android UA（包含 `YUNXH-YDAPP/1.0`），直接调用 H5 已使用的接口。

这是接口测试器，不代表真实 App 内停留的端到端测试。它不提前伪造停留时长、不绕过验证码或定位、不抽奖。它可能因为服务端环境校验、凭证或协议变化而失败；失败会停止，不保证一定能签到。

## 第一次怎么用

1. 建一个你自己管理的 **GitHub 私有仓库**。
2. 将本文件夹里的内容放到仓库根目录，保留 `.github/workflows/linping.yml` 路径。不要把整个 `linping-actions` 文件夹再套一层。Windows 中 `.github` 文件夹可能是隐藏的。
3. 仓库 `Settings → Secrets and variables → Actions → Secrets → New repository secret`，新增 `LINPING_TOKEN`，值填写你之前复制的 **Access-Token 本身**。不要加引号，不要粘贴整份请求头 JSON。代码中未内置真实 Token。
4. 在仓库 `Actions` 中找到“悦临平 H5 接口测试”，点击 `Run workflow`。第一次保持 `mode=inspect`。
5. 检查输出是否显示：测试账号 `19426008`、正确的当前金币余额、活动编号和今日签到状态。180 是你此前观察到的值，不是脚本固定余额。
6. 确认身份正确后，再次 `Run workflow`，选择 `mode=signin`，`max_wait_minutes=190`。如果还需要完整三小时，必须实际运行约三小时；可以关闭自己电脑上的网页，GitHub 的任务仍会运行。

只需要一个必填 Secret：`LINPING_TOKEN`。可选 `LINPING_DEVICE_ID` 是设备会话初始化使用的设备标识；一般先留空，脚本会生成一个，并按 H5 的 `_auth_dt` 流程取得设备令牌。这不是刷新用户 Token。不要把 App 密码或短信验证码填到这里。

## 两种运行方式

- `inspect`：获取设备会话、验证测试账号、读取公开活动规则、检查今日签到状态。不创建停留会话，不领取金币。
- `signin`：先做上述检查；今日未签到且没有额外验证限制时，创建停留会话，实际等待，每分钟请求一次 checkpoint。只采用服务端 `eligible` 状态，在提交前再次检查身份、今日记录、活动规则及会话资格，然后只尝试一次签到。最后检查今日记录和金币变化。

页面编号 `621` 不是签到活动编号。脚本从页面的 `signin` 组件读取活动 ID。2026-10-28 检查公开配置时，活动 ID 为 `10609040`，停留要求为 `10800` 秒（3 小时）；运行时会重新读取，不硬编码活动 ID。

请求签名包含随机值和当前时间，每次按当前 H5 逻辑重新生成，不复用你抓包里的旧 `Access-Api-Signature`。公开租户签名配置仅在运行进程中读取，不输出、不保存。程序不尝试伪造 App 原生登录信息。

## 定时运行（默认关闭）

请先手动成功测试，再到同一设置页的 **Variables** 标签新增仓库变量：

```text
ENABLE_SCHEDULE = true
```

模板设置为每天北京时间 20:17 启动，最长等待 190 分钟，实际启动可能延迟。每次独立创建测试会话，不把两次运行之间的空闲时间算作停留，也不保证能继承 App 会话进度。

想关闭定时，删除该变量或改成 `false`；想改时间，修改工作流的 `cron`（UTC）。手动触发仍可使用。

完整测试每天需要约 180 分钟运行资源，不是零时长任务。请先核对账号的 GitHub Actions 免费额度、费用和预算限制；私有仓库不等于无限免费。不要用多个仓库并发运行同一账号。工作流只限制本仓库并发，最终是否已签到仍由后端记录决定。

## Token 过期怎么处理

1. **目前能确定可用的方式**：在 App 正常登录后，重新打开这个 H5，从该页面成功请求中取得新的 `Access-Token`。只更新 GitHub 的 `LINPING_TOKEN` Secret，再手动跑 `inspect` 核对身份，无需改代码。
2. **自动续期还没有证据**：本次检查的 H5 登录链路中，没有确认可用的 `refresh_token` 接口。App 使用原生登录资料换取 H5 Token；仅有一个过期的 H5 Token，不能凭空换出新的登录凭证。
3. **以后可以接入的正规方式**：如果拿到项目正式的测试账号登录/刷新接口，或可安全提供的 App 会话刷新凭证，再单独实现续期；先验证新 Token 的账号一致后再使用。不能只修改 Token 内的时间字段。

每次请求更新的是 **接口签名**，不是 **用户 Token**。保持定时请求也不代表 Token 会自动续期。不能保证复制一次永久可用。

之前在聊天中公开过的 Token 建议测试后在 App 退出重登并确认旧令牌失效，或通过平台正式撤销。不要继续把新的 Token、完整请求头、HAR 抓包文件贴进聊天、Issue 或仓库。

## 常见结果

- **登录失效/需重新认证**：更新 Secret，先运行 `inspect`。不会反复尝试登录。
- **请求被拒绝（401/403）**：可能是登录、签名、设备或环境检查，不能直接断定只是 Token 过期。
- **业务码 1007**：服务器不认可当前资格；停止，未反复尝试。
- **达到等待上限**：没有成功累计所需进度，未提交。这里不伪造时长或直接尝试领取。
- **会话关闭/过期/结构变化**：本次停止，不无限重建会话。
- **签到接口成功但记录未确认**，或提交阶段超时：先到 App 看真实签到记录和余额，不要立即重跑。
- **今日已签到**：直接结束，不重复提交。

## 日志与验证范围

日志仅显示核对后的账号 ID、金币、活动 ID、时长进度和数字业务码。不输出 Token、动态签名、设备令牌、session ID、手机号、昵称或服务端原始响应。未启用抓包日志、截图或诊断文件上传。
